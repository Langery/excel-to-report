# 写作风格规范

## 四条铁律

1. **结论先行** —— 每段第一句就是这段最重要的话。读者只看每段第一句也能拿到全部关键信息。
2. **数字优先** —— 能用数字说的不用形容词。写"处理 47 件"，不写"处理了大量"。
3. **零编造** —— 报告中每个数字必须能在 read_table.py 的 JSON 输出里找到出处。表格没有的信息写"表中未提供"或留【待补充】，绝不脑补。这是本 Skill 的生命线。
4. **动词开头** —— 事项描述用"完成 XX / 推进 XX / 修复 XX"开头，不用"关于 XX 的工作"这种名词化句式。

## 语气分寸

- **对上汇报**：客观、克制、可核查。不用"圆满完成""重大突破"。数据好就说数字，数据不好就说原因和对策（表格里没有原因就写"原因待分析"）。
- **平级协作**：直接、信息密度高，少铺垫。
- 全程不用感叹号，不用"助力""赋能""抓手"这类词。

## 句式参考

| 场景 | 推荐 | 避免 |
|---|---|---|
| 概览 | 本周共处理工单 214 件，较上周（表外数据，待补充） | 本周工作有序开展 |
| 分组 | 其中华东区 89 件，占 41.6%，为最大来源 | 华东区贡献突出 |
| 异常 | 3 条记录超期未结，最长超期 12 天（工单 #1023） | 部分工单存在延期情况 |
| 收尾 | 下周计划【待补充】 | 未来将继续努力 |

## 数字书写规范

- 千分位：214,375 元（正文里金额加千分位，件数不加）
- 百分比保留 1 位小数：41.6%
- 均值/合计与表格 JSON 输出一致，四舍五入后如与 JSON 有出入以 JSON 为准
- 日期统一 YYYY-MM-DD

## 长度基准

- 周报初稿：300-600 字
- 汇报段落：100-200 字
- 分类叙述：每组 2-4 句，全文不超 800 字
- 异常清单：一 Problem 一行，不写评论性长句

用户要求"简短"时优先砍支撑句，保留结论句和核心数字。
