# 输出契约：读表 JSON 怎么读、怎么用

`../scripts/read_table.py` 吐出的 JSON，是本技能**唯一**的数字来源。报告里每个数字都必须能在这份 JSON 里找到出处。

这份文件回答三件事：

1. JSON 有哪些字段、每个字段什么意思（**照实写，不猜**）
2. 哪些数字可以直接抄，哪些必须自己算、怎么算才不出错
3. 读表失败时看哪句报错、怎么办

> 术语速查：**分组键** = 用来把行分类的那一列的取值（如"华东""2026-08"）；**聚合值** = 脚本对一组行算出的合计/均值等统计量；**原始数据** = 表里原样的单元格内容。

---

## 1. 三种模式

脚本有三种正常模式，靠命令行参数切换。三种模式输出的字段**不通用**，别混着读。

| 模式 | 命令 | 顶层 file_mode | 用来干什么 |
|---|---|---|---|
| 概览 | `../scripts/read_table.py <路径>` | `summary` | 看这张表有什么列、多少行、每列像什么类型 |
| 分组 | `../scripts/read_table.py <路径> --group <列名>` | `group` | 按维度出各组的行数与聚合值（写报告的主力） |
| 审计 | `../scripts/read_table.py <路径> --audit` | `audit` | 找空值/重复/离群/超期的候选信号（写异常清单用） |

三种模式的顶层都有 `ok`。成功时 `ok: true`，失败时 `ok: false` 并附 `error` 与 `hint` 两个字段，退出码 1。

### 1.1 概览模式（summary）

| 字段 | 类型 | 含义 | 模型怎么用 |
|---|---|---|---|
| `ok` | 布尔 | 恒为 true | 判断成败 |
| `file_mode` | 字符串 | 恒为 `"summary"` | 确认没跑错模式 |
| `sheets` | 数组或 null | 全部工作表名。**读 CSV 时是 null** | xlsx 多表时告诉用户有哪几张表可选 |
| `active_sheet` | 字符串或 null | 实际读到的那张表。读 CSV 时是 null | 报告里说"基于 XX 表"时的依据 |
| `row_count` | 整数 | **数据行数**（不含表头） | "共 N 条记录" |
| `columns` | 数组 | 每列的概况，逐列一项（见下） | 判断哪列能当维度、哪列能算数 |
| `sample_rows` | 数组 | 全表**前 N 行**原始行，N 由 `--rows` 决定（默认 5） | 看清数值长什么样、查具体行 |

`columns` 里每一项：

| 字段 | 类型 | 含义 |
|---|---|---|
| `name` | 字符串 | 列名。**CSV 里空表头会是空字符串**，xlsx 里是"列2"这种占位名 |
| `type` | 字符串 | `number` 数字 / `date` 日期 / `text` 文本 / `empty` 全空 |
| `non_empty` | 整数 | 该列有内容的格子数 |
| `unique_count` | 整数 | 该列有多少个不同取值 |

`type` 是**推断**出来的，规则是：非空值里数字占比 ≥ 80% 判 `number`，日期占比 ≥ 80% 判 `date`，否则 `text`。所以一列里混进少量文本（"N/A"）仍会被判成数字。

`sample_rows` 每项是"列名 → 单元格原始值"。**注意值不带类型统一**：读 CSV 时全是字符串（`"42"`），读 xlsx 时是真实类型（`42`），日期统一成 `"2026-08-15"` 这样的字符串。

### 1.2 分组模式（group）

| 字段 | 类型 | 含义 | 模型怎么用 |
|---|---|---|---|
| `ok` | 布尔 | 恒为 true | 判断成败 |
| `file_mode` | 字符串 | 恒为 `"group"` | 确认模式 |
| `group_column` | 字符串 | 按哪列分的组 | 报告里写清楚"按 X 划分" |
| `group_column_type` | 字符串 | 该列被判成的类型 | 判断"按月聚合"是否成立 |
| `bucketed_by_month` | 布尔 | **是否真的按月聚合了** | 见 2.4，是"能否按月叙述"的总开关 |
| `total_rows` | 整数 | 参与统计的总行数 | 分母 |
| `group_count` | 整数 | **分组总数**（不是 `groups` 的长度） | "共 N 个分组" |
| `truncated` | 布尔 | 组数超阈值被截断了 | 决定能不能声称覆盖了全部分组 |
| `numeric_columns` | 数组 | 参与统计的数值列名 | 知道哪些列有聚合值 |
| `date_columns` | 数组 | 参与统计的日期列名 | 知道哪些列有日期范围 |
| `groups` | 数组 | 各组统计结果，逐组一项（见下） | 报告的主要数字来源 |
| `sample_rows` | 数组 | 全表**前 N 行**原始行（与概览模式一样，不随分组变化） | 需要举例子时查这里 |

分组模式**没有** `sheets` / `active_sheet` 字段。也就是说分组结果里看不出读的是哪张表，报告若要声明数据来源，需自己记住 `--sheet` 参数。

`groups` 里每一项：

| 字段 | 类型 | 含义 |
|---|---|---|
| `group` | 字符串 | 分组键。空值组是 `"(空值)"`，识别不出的日期组是 `"(未识别日期: xxx)"` |
| `count` | 整数 | 该组**行数** |
| *数值列名* | 对象 | 该列在本组的聚合值 `{sum, avg, min, max}`。**该组内无有效数字时，这个键整个不存在** |
| *日期列名* | 对象 | 该列在本组的时间范围 `{earliest, latest}` |
| `merged` | 布尔 | 恒为 true，**仅合并组有** |
| `merged_from` | 整数 | 合并了几个组，**仅合并组有** |
| `merged_groups` | 数组 | 被合并的组名清单，**仅合并组有** |
| `avg_method` | 字符串 | 恒为 `"count_weighted"`，**仅合并组的数值聚合里有** |
| `value_count` | 整数 | 合并组里实际参与统计的数字个数，**仅合并组的数值聚合里有** |

被截断时（组数 > 30），`groups` 只给前 20 组 + 1 个合并组 `(其他 N 组)`，合并组排在最后。`truncated` 为 true。

### 1.3 审计模式（audit）

| 字段 | 类型 | 含义 |
|---|---|---|
| `ok` | 布尔 | 恒为 true |
| `file_mode` | 字符串 | 恒为 `"audit"` |
| `row_count` | 整数 | 数据行数（不含表头） |
| `row_numbering` | 字符串 | 行号含义说明 |
| `disclaimer` | 字符串 | 免责说明：所有条目都是**候选信号**不是结论 |
| `columns` | 数组 | 列名/类型/非空数（**比概览模式少 `unique_count`**） |
| `empty_values` | 对象 | 空值检测结果 |
| `duplicates` | 对象 | 重复值检测结果 |
| `outliers` | 对象 | 离群值检测结果 |
| `mixed_date_formats` | 对象 | 同一日期列内格式混用检测 |
| `overdue` | 对象或 null | 超期检测结果。**没给超期参数时为 null** |
| `overdue_skipped` | 对象 | `overdue` 为 null 时，说明缺哪些参数、为什么不给 |

**行号含义**：审计模式所有条目里的 `row` 是**数据行序号**（第 1 行数据算第 1，不含表头）；`excel_row` 是**文件里的物理行号**（含表头，比 `row` 大 1）。写异常清单时给用户看 `excel_row`，这样他点开表就能定位。

**审计模式不产出结论**，只产出"位置 + 原始值 + 所用方法"。脚本刻意不猜"什么状态算未完成"这类语义 —— 猜错会直接产出错误的超期名单。要判超期必须显式传 `--due-col`、`--status-col`、`--unfinished-values`。

## 2. 数字纪律：什么能抄，什么得自己算

这是本技能的生命线。原则是：**报告里每个数字都能在读表 JSON 里指到出处**。

### 2.1 原始数据 —— 可直接引用

这些是表里原样搬过来的，抄进报告不会有口径问题：

- `sample_rows` 里的单元格值
- `row_count`、`total_rows`、`count`、`non_empty`、`unique_count`
- `groups[].group`（分组键本身就是表里的值）

引用时的唯一纪律：**注明这些数字的口径**。`count` 是行数不是对象数（同一笔业务拆成 3 行就记 3），`non_empty` 是有内容的格子数不是总数。

### 2.2 脚本算好的聚合值 —— 可直接用

- `groups[].<数值列>.{sum, avg, min, max}`
- `groups[].<日期列>.{earliest, latest}`
- 审计模式里的计数类结果：`empty_values` 的 `empty_count`、`duplicates` 的 `duplicate_group_count` / `duplicate_row_count`、`overdue` 的 `overdue_count`、`items[].overdue_days`

审计模式每个检测项都带一个 `confidence` 字段，它是**引用前必看的开关**：

| confidence 取值 | 含义 | 报告里怎么写 |
|---|---|---|
| `确证` | 客观事实，不依赖主观判断（空值检测） | 可直接引用 |
| `确证（格式差异客观存在）` | 事实成立，但"是否算问题"要用户判断（日期格式混用） | 可引用，但写成"同一列有 N 种写法"，别直接判为错误 |
| `确证（口径由调用方显式给定，非脚本推断）` | 事实成立，但成立范围是你给的口径（超期检测） | 可引用，但必须连口径一起写（如"按你给的未完成状态判定"） |
| `启发式候选` | 只是线索，可能合法（重复值、离群值） | **不能写成事实**，要先跟用户确认 |

实跑确认的取值就这四种（逐项实跑核对过）。引用前先看这一项再决定措辞。

用之前先看聚合值存不存在。**键不存在 ≠ 0**。某组内该列没有有效数字时，脚本**整键不给**（不是给 0、不是给 null）。例：组"华北"的"订单数"键缺失，正确写法是"该组订单数无有效数据"，写"华北订单数 0"就是编数字。

### 2.3 脚本不给、必须自己从 rows 算的

以下六类脚本**从不**输出，只能自己算。算的时候必须把分母口径写进报告。

| 要算什么 | 怎么算 | 易错点 |
|---|---|---|
| 占比 / 百分比 | 某组 `sum` ÷ 全部组 `sum` 之和 | 脚本**不输出任何百分比**，占比一律自算。分母是"全部组的 sum 之和"，不是 `total_rows` |
| 环比 / 同比 | 拿两期结果相减或相除 | 一次分组只给一个维度，**跨期比较要自己跑两次**并说明依据 |
| 完成率 / 达成率 | 表里同时有"完成数"和"应完成数"才能算 | 表里只有完成数 → 写"表中未提供"，不能反推 |
| 跨组整体均值 | 各组 `sum` 相加 ÷ 参与统计的数字个数 | **不能对各组 `avg` 取算术平均**。实跑对照：合并组加权均值 12.5，简单平均 11.82，差 0.68 |
| 某组 `avg` 的分母 | **实际参与统计的数字个数**，未必等于 `count` | 组内有空值/非数字时，`avg` 的分母比 `count` 小。脚本对普通组**不告诉你这个分母**（只有合并组给 `value_count`），要自己从 `sample_rows` 数 |
| 文本列的取值数 | 概览模式的 `columns[].unique_count` | 分组模式**不输出**文本列的取值数 |

**"键缺失"的三个来源**（都会让模型误算，交付前逐个查）：

1. 组内该数值列无有效数字 → 聚合键缺失
2. 组内部分行数字无效（空值、`N／A`）→ `avg` 分母 ≠ `count`
3. 合并组里某数值列全无值 → 合并组内该列的键也缺失

### 2.4 分组键的排序规则

**排序规则随 `bucketed_by_month` 变，两种情况的含义完全不同。**

**情况一：`bucketed_by_month` 为 true（分组列被判为日期）**

- 按 `YYYY-MM` **时间升序**排列，与各组行数多少无关。实跑：月份列 7 月 1 行、8 月 2 行、9 月 1 行 → 输出仍是 7、8、9
- 特殊组 `(空值)` / `(未识别日期: xxx)` **恒排最后**
- 这时 `groups` 的顺序可以直接当时间轴用，报告里能写"从 7 月到 9 月"

**情况二：`bucketed_by_month` 为 false（分组列不是日期）**

- 按 `count` **行数降序**排列。实跑：华东 3 行、华南 2 行、华北 1 行 → 顺序即如此
- 行数相同时，按表里**首次出现的先后**排
- 这时 `groups` 的顺序**不是**"重要性"也不是"时间顺序"，只是"量从大到小"。报告里写"重点是前几组"要注明是按行数排的

**组数超阈值时**：`groups` 只有前 20 组 + 1 个合并组。`group_count` 才是真实总数（实跑 `group_count: 53` 而 `groups` 长度 21）。报告里说"共 53 个分组"用 `group_count`，但**不能说"详细列了 21 个组"就当全覆盖** —— 其余 33 组的聚合值在合并组里。

### 2.5 浮点数、百分比、金额的呈现约定

**脚本给的是原始精度，不是格式化好的字符串。** 所有 `sum` / `avg` / `min` / `max` 都四舍五入到 2 位小数后以**数字**形式输出。实跑原样（一张 3 行销售表的分组结果）：

```json
{
  "group": "华东",
  "count": 1,
  "订单数": { "sum": 42.0, "avg": 42.0, "min": 42.0, "max": 42.0 },
  "销售额": { "sum": 185000.0, "avg": 185000.0, "min": 185000.0, "max": 185000.0 }
}
```

注意是 185000.0 这种裸数字，**不是** "185,000.00 元" 这种格式化文本。千分位、百分号、货币符号**脚本一律不加**，加不加由你按写作规范决定。

- **千分位**：正文金额加千分位（`214,375 元`），件数不加
- **百分比**：保留 1 位小数（`41.6%`），由你在正文里自行换算，脚本不产出百分比
- **日期**：统一 `YYYY-MM-DD`；只到月的原始值（`2026-08`）在分组键里保持 `YYYY-MM`
- **以 JSON 为准**：正文数字与 JSON 不一致时以 JSON 为准。若你手算的均值和 `avg` 对不上，先怀疑分母（见 2.3）

**浮点陷阱**：脚本的 `sum` 已四舍五入到 2 位，0.1 加 0.2 输出 0.3。但自己从 `sample_rows` 逐个相加会得到 0.30000000000000004 这种长尾。**不要自己重算已有聚合值**，直接用 JSON 里的。

**涉钱精度**：脚本固定保留 2 位。表里若有 3 位以上小数（如单价 0.005 元），四舍五入会吃掉精度 —— 这时要在报告里提一句口径，或请用户确认是否可接受。

## 3. 读表失败与出路

失败时 stdout 一定是这个形状，`ok` 为 false，`error` 说发生了什么，`hint` 说怎么办：

```json
{
  "ok": false,
  "error": "具体出了什么事",
  "hint": "接下来怎么办"
}
```

### 3.1 缺 openpyxl（读 xlsx 时最常见）

环境里没装 openpyxl 时，真实报错文案是：

```
"error": "当前环境缺少 openpyxl，无法读取 xlsx",
"hint": "安装：pip install openpyxl；或改用平台内置表格读取能力，或请用户提供 CSV 版本的同一张表（CSV 路径纯标准库，无需依赖）"
```

三条出路，按推荐顺序：

1. **请用户在 Excel/WPS 里另存为 CSV**（最稳）。CSV 路径纯标准库，不装任何东西就能跑，中文、GBK 编码、分隔符都自动识别
2. 装 openpyxl 后重跑：`pip install openpyxl`
3. 改用平台内置的表格读取能力

不要因为这条报错就中止任务 —— 换 CSV 路径通常能立刻继续。

### 3.2 其他真实报错与出路

| 报错文案（`error` 字段） | 原因 | 出路 |
|---|---|---|
| `暂不支持旧版 .xls 格式` | 传了 `.xls` | 让用户另存为 `.xlsx` 或导出 CSV |
| `不支持的文件类型` | 传了 `.txt` / `.pdf` 等 | 换成 `.xlsx` / `.xlsm` / `.csv` |
| `读取失败: [Errno 2] No such file or directory: '...'` | 路径不对 | 请用户给完整路径；路径含空格或中文时用引号包起来 |
| `读取失败: [Errno 13] Permission denied: '...'` | CSV 没有读取权限 | 确认文件存在且当前用户可读 |
| `无法打开 xlsx 文件: [Errno 13] Permission denied: '...'` | xlsx 权限不足 | 关掉 Excel/WPS 再重试，或请用户另存一份到别的位置 |
| `无法打开 xlsx 文件: File is not a zip file` | xlsx 损坏或其实是别的格式改了后缀 | 重新导出 |
| `无法打开 xlsx 文件: <其他异常>` | 提示里点名了三种可能：路径错、文件损坏、文件加密 | 按这三种逐一排查：核对路径、重新导出、让用户去掉密码保护 |
| `无法识别 CSV 文件编码` | 文件其实是 Excel 二进制（xlsx 改了名） | 改回正确后缀，或真的用 Excel 另存为 CSV |
| `表头为空或表格无数据` | 文件是空的，或第一行不是列名 | 确认表格第一行是列名 |
| `分组列「X」不存在` | `--group` 的列名拼错 | `hint` 里列了可用列名，照着改 |
| `缺少表格文件路径` | 没传路径 | 补上文件路径 |

**关于编码**：中文 Excel 导出的 CSV 常见是 GBK 编码，脚本会依次尝试 `utf-8-sig` / `gb18030` / `utf-8` 自动识别，**实跑确认 GBK 中文 CSV 能直接读出中文列名，不需要任何额外处理**。只有在文件根本不是文本 CSV 时才会报"无法识别编码"。

**关于"文件被 Excel 占用"**：文件被占用时脚本报的是权限错误（见上表）。出路：关掉 Excel/WPS 后重试，或请用户另存副本到别的位置。

### 3.3 表格本身的数据坑（不报错，但结果会错）

这几类情况脚本**不会失败**，但会静默给出容易写错报告的数据。读表后必须主动检查。

**坑一：合并单元格**

xlsx 里合并单元格区域只有第一行有值，其余行该列为 null。后果：按这列分组会**多出一个 `(空值)` 组**，数据被拆散。实跑：合并成"技术部"的 2 行 → 分组出 `技术部`(1 行) + `(空值)`(1 行)。

出路：告诉用户合并单元格会让按这列分组不准，建议取消合并、或改按别的列分组、或从 `sample_rows` 手工核对。**绝不能把 `(空值)` 组当成一个真实部门写进报告。**

**坑二：日期列存成 Excel 序列号**

Excel 内部把日期存成 45839 这样的整数。若表格是 CSV 且日期列没被格式化，脚本会把它判成 `number`，分组键就是裸数字 `"45839"`，`bucketed_by_month` 为 false，**并且没有任何警告**。

出路：让用户在 Excel 里把该列设成日期格式再另存 CSV，或另加一列文本月份（`YYYY-MM`）再按它分组。模型必须主动查：分组键是一串纯数字、而列名像日期 → 立刻向用户确认口径，不要默默按数字分组。

**坑三：表头不规范**

| 情况 | 表现 | 出路 |
|---|---|---|
| CSV 里某列没有表头 | `columns[].name` 是空字符串，但 `sample_rows` 里该列的键是"列2"这种占位名，**两者对不上**；该列的统计恒为 0（`type: empty`） | 读表后核对 `columns` 与 `sample_rows` 的列名是否一致；不一致就请用户补表头 |
| 重复表头（两列同名） | **先出现的那列数据被后出现的那列覆盖，永久丢失**。实跑：两列都叫"金额"，只留下 999/888，100/200 消失 | 同上，必须让用户改表头再读 |
| 多个空表头 | 列数与 `sample_rows` 的键数对不上，数据可能错位 | 同上 |

**这类问题必须在概览阶段就发现并报告**，别等到写完报告才发现数字少了。

## 4. 交付前的数字自检清单

交稿前逐条过一遍。每条不通过就回去改，**不要交出去再说"大致是这样"**。

**溯源**

1. 报告里每一个数字，都能指到 JSON 里的具体位置吗？（例如"华东 42 件"→ `groups[0].订单数.sum`）
2. 有没有哪个数字是"看趋势估出来的"？有就删掉或标为推断
3. 表里没有的信息，写的是"表中未提供"或【待补充】吗？

**分组口径**

4. 用的是 `group_count`（真实组数）还是 `groups` 的长度（截断后只有 21）？说"共 N 组"时用前者
5. `bucketed_by_month` 是 true 吗？只有 true 才能按时间顺序叙述；false 时 `groups` 是按行数降序，别当时间轴用
6. 合并组（`(其他 N 组)`）在报告里注明了是"其余 N 组的合计/均值"吗？没注明就是把合并值当单组用了
7. `(空值)` / `(未识别日期: ...)` 组有没有被当成真实分类写进报告？这两组是**数据问题**，要单独提示用户

**算术**

8. 跨组均值是用 `sum` 相加 ÷ 数字个数算的，还是对各组 `avg` 取了算术平均？后者一定错
9. 有没有组的 `avg` 分母 ≠ `count`（组内有空值或 `N／A`）？有的话报告里的均值口径要说明，或改用 `sum`
10. 聚合键缺失的组，写的是"无有效数据"还是被当成 0 了？写成 0 就是编数字
11. 占比的分母写清了吗？（"占全表 42.0%"到底是按金额还是按件数）
12. 有没有自己从 `sample_rows` 重算了脚本已经给过的聚合值？重算会和 JSON 对不上，直接用 JSON

**呈现**

13. 正文数字与 JSON 一致吗？不一致时以 JSON 为准
14. 金额加了千分位、件数没加吗？百分比保留 1 位小数吗？
15. 涉及小于 2 位小数的金额时，提过精度口径吗？

**表质量**

16. 概览阶段发现的表头问题（空表头、重名列、列名对不上）报告给用户了吗？
17. 合并单元格导致的多余 `(空值)` 组，提示用户了吗？
18. 日期列是 Excel 序列号（分组键是纯数字）的情况，向用户确认过口径了吗？
19. 审计模式给出的候选信号，写成"事实"了吗？先看每项的 `confidence`：标着 `启发式候选` 的（重复值、离群值）只是线索，没经用户确认就写"XX 已超期"属于越界
20. 审计模式超期检测返回 `overdue: null` 时，是否已经追问用户"什么状态算未完成"？没问就下超期结论是编造
